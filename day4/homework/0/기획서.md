### 자주 하는 작업
- **못 맞힌 정답을 후보로 추가** (4절 "못 맞힌 정답 반영"): 기록 확인 → `data/topics/<주제>.mjs` 에 후보 추가 → `build-table-<주제>` 실행(새 후보 줄만 채움) → `npm run deploy`
  - 창고 뒤지기로 찾아 맞힌 목록 밖 정답도 정식 후보로 옮길 후보다: 로컬 `.data/found.json`, 배포 KV `found:` 키 (`npx wrangler kv key list --binding KV --remote --prefix found:`)
  - 로컬 기록: `npm run losses`
  - 배포 사이트 기록은 KV에 있다: `npx wrangler kv key list --binding KV --remote --prefix loss:` 로 목록을 보고 `npx wrangler kv key get <키> --binding KV --remote` 로 내용을 본다 (`npm run losses` 는 로컬 파일만 읽음)
- **질문 문구 수정**: 문구를 고친 뒤 그 주제를 `node scripts/build-table.mjs <주제> --all` 로 다시 채운다. 고친 뒤에는 질문마다 Jev가 "예"라고 본 후보를 훑어서 글자 그대로 해석하지 않았는지 확인한다 (2절 주의 참고).
- **루소 포즈 다시 그리기**: `node scripts/make-russo.mjs [포즈...]` (OpenAI 키 필요, 중간 품질·투명 배경)
- **그림 화풍을 바꿨을 때**: 이미 저장된 그림은 그대로 나오므로 지워야 다시 그려진다. 로컬은 `.data/images/` 파일 삭제, 배포는 KV의 `img:<주제>/<후보>` 키를 지우고 `actor:<주제>/<후보>` 의 image 항목을 없앤다.
- **로컬 그림을 배포로 옮기기**: `node scripts/seed-kv.mjs`

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 이름 | **루소 목공소** (처음 이름 "뚝딱 루소"에서 변경) |
| 한 줄 소개 | 사용자가 마음속으로 정답을 떠올리면, 목수 루소가 질문으로 좁혀가며 맞히는 스무고개 웹 게임 (아키네이터 방식) |
| 목적 | 사내 AI 에이전트 강의 과제. 조건: 흥미 위주 마이크로 서비스, OpenAI가 아니어도 됨, **Jev를 포함한 여러 API 활용**, **배포까지**, 고도화는 불필요 |
| 대상 | 사내 동료 |
| 환경 | **PC 웹사이트**. 모바일은 화면이 깨지지 않는 정도만 대응 |
| 진행자 | 키글(KIGLE) 캐릭터 **루소** (안킬로사우루스, 목수) |
| 배포 | Cloudflare |

**콘셉트**: 목수 루소가 "오늘은 뭘 만들어 드릴까요? 아저씨가 맞혀볼게요!" 하고 스무고개로 사용자가 원하는 것을 맞힌다. 맞히면 "그럼 이제 만들어 볼까요?" 하고 뚝딱뚝딱 깎아서, 키글 캐릭터가 정답을 흉내 낸 **목각인형**을 만들어 준다. (2026-10-17 사용자 요청으로 변경)

**핵심 목표 (이것만 만든다)**
1. 루소가 테이블 건너편에서 질문하고, 사용자는 버튼으로 답한다.
2. 답변을 보고 정답을 좁혀가는 판단은 **Jev**에게 맡긴다.
3. 맞히면 루소가 만드는 연출 뒤에 **키글 캐릭터가 정답을 흉내 낸 목각인형 그림**을 보여준다.

**하지 않을 것**
- 아키네이터의 지니 그림, 로고, 이름을 따라 쓰지 않는다. 진행 방식만 참고한다.
- 사용자가 맞히는 모드는 만들지 않는다. 루소가 맞히는 모드만 만든다.
- 뽀로로 등 외부 라이선스 캐릭터는 흉내 배우로 쓰지 않는다. 코코비 세계관 캐릭터만 쓴다.
- 13절 "만들지 않는 것"에 적힌 기능은 과제 범위 밖이므로 추가하지 않는다.

## 2. 주제와 데이터

- **주제 3개**: 동물 / 음식 / 인물·캐릭터
- **후보**: 동물 51, 음식 50, 인물·캐릭터 100. 목록 밖 정답은 맞히지 못한다 (정상 동작으로 본다). 못 맞힌 정답은 4절 방식으로 추가한다.
- **질문 목록**: 주제당 55개 (2026-10-18 초반이 단조롭지 않게 5개씩 추가: 동물 "귀여운 동물로 인기가 많나요?", "고양이보다 몸집이 작나요?" 등, 음식 "단 음식보다는 짜거나 매운 음식 쪽인가요?", "야식으로 많이 먹나요?" 등, 인물 "1990년대 이전에 처음 유명해졌나요?", "모험을 떠나는 이야기의 주인공인가요?" 등). 개발할 때 Claude Code로 작성한다.
- **Jev 판단 표**: 후보 × 질문마다 "이 후보는 이 질문에 '예'일 확률" (0~1). 50 × 50 × 3 = **약 7,500칸**. 개발할 때 Jev로 미리 채운다.
- **흉내 묘사 문장(mimic)**: 후보마다 "키글 캐릭터가 이 정답을 어떻게 흉내 내는지" 한두 문장. 개발할 때 Claude Code로 작성한다.

판단 표 예시 (값은 설명용):

| 후보 | 날 수 있나요? | 다리가 4개? | 물에서 살아요? |
|---|---:|---:|---:|
| 펭귄 | 0.05 | 0.02 | 0.80 |
| 고양이 | 0.01 | 0.97 | 0.05 |
| 독수리 | 0.97 | 0.02 | 0.03 |

**인물·캐릭터 후보 기준** (2026-10-17 사용자 결정)
- **외부 캐릭터(피카츄, 뽀로로, 엘사 등)도 후보에 넣고, 맞히면 목각인형도 만든다.** 비상업 사내 과제라는 이유로 사용자가 선택했다. 흉내 배우는 여전히 키글 캐릭터만 쓴다.
- 프롬프트에는 캐릭터 이름을 넣지 않고 특징(색, 의상, 소품)만 쓴다. 이미지 모델이 거부하면 나무 명패만 보여준다.
- **정치인**: 현역·최근 정치인은 넣지 않는다. 세종대왕, 이순신, 링컨처럼 오래전 역사 인물만 넣고, 논란이 큰 인물(독재자 등)은 제외한다.
- **현역 유명인**: 논란 없는 운동선수·연예인 위주로 10명 정도 넣는다. 그림에는 이름 없이 의상·소품만 쓴다.
- **구성 (100명)**: 역사·위인 20 + 동화·전래·고전 14 + 외부 캐릭터 24 + 기업가 4 + 현역 유명인(국내외 연예인·운동선수) 34 + 직업 4
- **보강 이력 (2026-10-17)**: 처음 51명일 때 배포 사이트에서 못 맞힌 3판이 모두 목록 밖 인물이었다 (일론 머스크 2번, 도널드 트럼프 1번). 그래서 기업가, 해외 스타, 한국 연예인·운동선수, 캐릭터를 49명 더 넣고, 거의 가르지 못하던 질문 6개(모자, 노란색, 특별한 옷차림, 머리 모양, 말버릇, 남을 돕는 일)를 기업가, 배우, 아이돌, 미국, 축구 선수, 소설 속 주인공 질문으로 바꿨다. 트럼프는 현역 정치인 제외 기준대로 넣지 않았다.
- 인물은 성별을 적어 두고(6절 배우 고르기 규칙), 캐릭터처럼 성별이 애매하면 비워 둔다.

**질문 문구 주의 (Jev 판단 품질)**: Jev는 질문을 글자 그대로 판단한다. "아프리카에 사나요?"에 개미도 "예", "동물원에서 볼 수 있나요?"에 비둘기도 "예"라고 답했다. 그래서 질문은 사람들이 떠올리는 뜻으로 쓴다 (예: "아프리카 하면 떠오르는 동물인가요?", "동물원에 가야 볼 수 있는 동물인가요?", "튀김처럼 바삭바삭한 식감인가요?"). 세 주제 모두 이렇게 문구를 고친 뒤 다시 채웠다.

## 3. AI 역할 분담

핵심 원칙: **판단은 Jev, 계산은 코드, 그림은 이미지 API.** Jev는 문장을 생성하지 않고, 주어진 보기 중 선택하거나 확률을 판단만 한다.

| 작업 | 담당 | 시점 |
|---|---|---|

## 4. 게임 진행

### 답변 방식
- 버튼 5개: **예 / 아마도요 / 모르겠어요 / 아마 아닐걸요 / 아니요**
- 키보드 단축키 1~5
- 자유 입력(타이핑)은 없다.

| 버튼 | 확률 계산 반영 |
|---|---|
| 예 | 강하게 반영 |
| 아마도요 | 약하게 반영 |
| 모르겠어요 | 반영하지 않음 |
| 아마 아닐걸요 | 반대로 약하게 반영 |
| 아니요 | 반대로 강하게 반영 |

- **후보는 답변 하나로 지우지 않는다.** 확률만 조정해서 사용자의 실수나 판단 기준 차이(예: "토마토는 과일인가요?")를 회복할 수 있게 한다. 판단 표 값이 0이나 1이어도 계산할 때는 작은 여유를 둬서 확률이 0이 되지 않게 한다.
- **이전으로**: 바로 앞 답변을 취소하고 그 질문으로 돌아간다. 확률은 남은 답변으로 다시 계산한다.

### 진행 순서 (수치는 `public/game.js` 의 RULES: 최대 질문 20, 최소 질문 5, 추측 기준 확신도 0.6, 재추측 3회, 재추측 전 질문 2~3개)

추측 기준은 처음 0.8이었다. 인물을 100명으로 늘린 뒤 모의 게임으로 비교해 보니, 0.6이 세 주제 모두 정답률은 같거나 조금 높고 질문이 약 3개 적었다 (인물 평균 17.9개 → 15.0개). 그래서 0.6으로 바꿨다.

1. **질문**: 판단 표를 보고 남은 후보를 가장 잘 갈라주는 질문을 고른다. 답변마다 확률을 갱신한다. **처음 3개 질문은 잘 가르는 질문 상위 5개 중 무작위**로 골라서 매번 시작이 달라진다 (2026-10-18, RULES.variedFirst/variedPool. 모의 게임에서 정답률 차이는 오차 수준, 질문 +0.3개).
2. **추측**: 1위 후보 확신도가 기준을 넘거나 질문 **20개**에 도달하면 추측한다.
3. **재추측**: 틀리면 그 후보만 확실히 제외하고 질문을 2~3개 더 한 뒤 다시 추측한다. 재추측은 **최대 3회**.
4. **끝**
   - 맞히면 → 정답 공개 (5절)
   - 재추측까지 다 틀리면 → "졌어요" 화면. 정답을 입력받아 **기록만** 남긴다 (자동 반영, 검사, 승인 없음). 나중에 후보를 보강할 때 참고한다.

### 창고 뒤지기: 목록 밖 정답 찾기 (2026-10-18 사용자 요청으로 추가)
목록에 없는 정답(예: 인물 주제에서 목록 밖 사람)을 너무 못 맞혀서, 판단 표로 못 맞히면 LLM이 후보를 떠올리고 Jev가 검증하는 단계를 넣는다. 처음 기획에 있다가 13절로 뺐던 기능을 사용자 요청으로 다시 살렸다.

1. 판단 표로 추측하다가 **두 번 틀리면** (처음 추측 + 재추측 1번) 창고 뒤지기로 넘어간다. 루소: "가만있자, 창고에 다른 재료가 있나 볼게요~"
   - **루소의 질문 (2026-10-19 사용자 요청으로 추가)**: 창고에 가기 전에 LLM이 지금까지의 질문·답을 보고 판단 표 55개 밖의 새 예/아니요 질문을 **답을 보고 하나씩, 2개**(`ASK_COUNT`) 만든다 (예: "유튜브 채널을 운영하며 유명해졌나요?" → 예 → "영어가 아닌 다른 언어로 방송하는 크리에이터인가요?"). 답은 지금처럼 버튼 5개로 받고, 이 동안 "이전으로"는 막는다. 질문 하나에 약 2~3초. 루소: "허허, 이건 좀 어렵네요. 몇 가지만 더 여쭤볼게요~" → "💬 이건 어때요?"
   - 이 답은 아래 2)의 LLM 후보 떠올리기와 4)의 Jev 점수 매기기에 판단 표 질문과 똑같이 들어간다. 질문 문장은 서버가 서명해서 화면에 맡겼다가 돌려받는다 (화면이 문장을 바꿀 수 없게, `type: 'ask'`).
   - 키가 없거나, 관리 페이지에서 창고 뒤지기를 껐거나, 상한을 넘었거나, LLM이 실패하면 질문 없이 바로 창고 뒤지기로 간다.
   - 코드: `lib/llm.mjs` `askQuestion`, `lib/search.mjs` `storageAsk`, `/api/ask`, `public/app.js` `askNext`.
2. **LLM (Claude 글 모델, `CLAUDE_MODEL` 기본 `claude-sonnet-5-5`, `CLAUDE_EFFORT` 기본 low. 구조화 출력으로 JSON 고정, 안전 분류기가 거절하면 `fallbacks: "default"` 로 다른 모델이 이어 받음)** 이 지금까지의 질문·답을 보고 후보 이름 15개와, 상위 후보들을 가르는 질문 최대 3개를 떠올린다 (약 4~6초). 그림용 설명(as)과 흉내 묘사(mimic)는 맞혀서 목각인형을 처음 만들 때 그 1개만 쓴다 (만드는 연출 중이라 기다림이 안 느껴짐).
3. 판단 표에서 아직 남은 상위 후보 5개도 함께 넣는다 (목록 안 정답을 놓치지 않게).
4. **Jev** 가 후보마다 "이 후보를 떠올린 사람이 이 질문들에 이렇게 답했을까"를 판단해 점수를 매긴다. 인물 주제에서는 Jev가 "현역·최근 정치인이거나 범죄자, 범죄·추문으로 알려진 인물인가"도 판단해서 걸러 낸다 (LLM 지시문에도 같은 기준을 넣음).
5. 점수 상위 **5개를 차례로 추측**한다 (점수 = Jev 점수 + LLM이 떠올린 순서 가산점. 비슷한 후보끼리는 Jev 점수 차이가 작아서 LLM 순서를 기본으로 하고, Jev는 답과 크게 어긋나는 후보를 뒤로 민다): "창고에서 찾았어요! 혹시… ○○ 만들어 드릴까요?" 맞히면 목각인형을 똑같이 만들고, 다 틀리면 "못 맞힘" 화면으로 간다.
   - **줄자로 재기 (2026-10-18 추가)**: 1위와 2위 점수가 비슷하면(차이 4 미만. LLM 순서 가산점만으로도 1.4쯤 벌어져서 넉넉히 잡음) 추측 전에 질문을 1~3개 더 한다. 질문은 LLM이 후보를 떠올릴 때 함께 만든 "상위 후보들을 가르는 예/아니요 질문"이다 (예: "무한도전에 나왔나요?"). 루소: "요 두 개가 아주 비슷하네요. 딱 하나만 재볼게요." 답을 받으면 Jev가 상위 12개 후보마다 그 질문들도 판단해서 점수를 다시 매긴 뒤 추측한다. 이때는 가르려고 만든 질문이라 답을 2배로, LLM 순서는 1/4로 반영한다. 후보 목록은 서명해서 화면에 맡겼다가 돌려받는다 (서버는 상태를 들고 있지 않음).
6. 창고에서 찾은 정답은 서버만 아는 서명을 붙여 화면에 넘기고, 맞혔을 때만 저장한다 (`found:<주제>/<id>`). 그래서 화면에서 임의의 그림 설명을 보내 그림을 그리게 할 수 없다. 저장된 것은 공유 페이지와 TOP 5에도 쓰이고, 개발자가 나중에 정식 후보로 옮길 때 참고한다.
- 하루 상한: `DAILY_SEARCH_LIMIT` (기본 300번). 넘으면 창고 뒤지기 없이 바로 "못 맞힘"으로 간다. 루소의 질문도 LLM을 부르므로 같은 상한에서 1번씩 센다 (창고까지 가는 게임 1판에 3번).
- 비용: 한 번에 LLM 3번(루소의 질문 2 + 후보 떠올리기 1) + Jev 약 15번, 몇 원 수준. 몇 초 걸린다.

### 못 맞힌 정답 반영 (A 방식: 개발자가 직접 추가, 2026-10-17 결정)
- 게임이 스스로 배우지는 않는다. 못 맞힌 정답은 기록만 쌓이고, 개발자가 모아서 후보에 추가한다.
- 순서: `npm run losses` 로 자주 나온 정답 확인 → `data/topics/<주제>.mjs` 에 후보 추가 (이름, 영어 이름, 성별, 그림용 설명 as, 흉내 묘사 mimic) → `node scripts/build-table.mjs <주제>` 로 **새 후보 줄만** Jev가 채움 (1명당 약 1초, $0.0002) → 로컬은 서버 다시 켜기, 배포는 `npm run deploy`
- 질문 문구를 고쳤을 때는 `--all` 로 그 주제 전체를 다시 채운다 (약 3초, $0.01).
- 지금까지 반영: 인물·캐릭터에 카리나, 동물에 티라노사우루스 추가. 인물·캐릭터는 2절 "보강 이력"처럼 한 번에 49명을 늘렸다.
- 비슷한 후보끼리(예: 카리나와 블랙핑크)는 갈라주는 질문이 없어서 맞히는 데 질문 20개까지 걸릴 수 있다. 자주 문제가 되면 둘을 가르는 질문을 하나 넣는다.

## 5. 정답 이미지 (루소가 만든 목각인형)

- **배우 캐릭터가 정답을 흉내 낸 모습을 깎은 목각인형**이다. 의상, 포즈, 소품까지 나무로 깎은 것처럼 그린다.
  - 동물: 펭귄 → 펭귄 옷을 입고 뒤뚱거리는 코코 목각인형
  - 음식: 사과 → 커다란 사과를 든 러비 목각인형
  - 인물: 손흥민 → 흰색 축구 유니폼 7번에 카메라 세리머니를 하는 잭잭 목각인형
- 프롬프트에는 **실제 이름을 넣지 않고** 2절의 흉내 묘사 문장(특징)만 넣는다.
- **화풍**: 밝은 원목, 나뭇결과 끌 자국이 보이고 무광 물감을 얇게 칠한 수제 나무 장난감. 작업대 위에 서 있고, 뒤는 흐릿한 목공 작업실. 배우의 원본 이미지(`assets/characters/`)를 참고로 함께 넣어 생김새를 맞춘다.
- **글씨는 이미지 안에 넣지 않는다.** 정답 이름은 웹 화면의 나무 명패에 쓴다.
- **생성 시점**: 미리 만들지 않는다. 정답이 공개될 때 배우 고르기(Jev) → 이미지 생성(OpenAI) → 저장(배포는 Workers KV).
- **정답당 최대 2장** (2026-10-18, `IMAGES_PER_ANSWER`): 처음 맞히면 1장째, 두 번째로 맞히면 **다른 배우로** 2장째를 그리고, 그 뒤로는 저장된 2장 중 하나를 무작위로 쓴다. 공유 링크는 본 그림 번호(`&n=1`)를 기억한다. 비용은 정답당 최대 2장으로 묶인다.
- **품질**: 저품질(low). 실측 장당 약 15~18초.
- **하루 생성 상한**: 50장 (`DAILY_IMAGE_LIMIT`). 오늘 생성 수는 저장소에 한국 시간 기준으로 센다.
- **생성 실패나 상한 초과 시**: 나무토막 그림과 정답 명패만 보여준다.
- 인터넷 이미지는 쓰지 않는다 (저작권, 그림체 불일치).

## 7. 진행자 루소 연출

### 루소 설정
- 키글 캐릭터, 안킬로사우루스, 직업은 소방관·목수. **이 게임에서는 목수로만 연출한다.**
- 생김새: 베이지 몸, 굵은 일자 눈썹, 파란 털모자, 흰 셔츠, 노란 단추의 파란 멜빵바지, 머리의 땀방울

### 콘셉트
- 사용자는 루소의 작업실에서 **테이블을 사이에 두고 루소와 마주 앉아** 대화한다. 루소는 허리 위로 크게 보이고, 답 버튼은 테이블 위에 놓인다.
- 루소가 사용자가 만들고 싶은 것을 스무고개로 맞힌다. 추측도 "혹시… ○○ 만들어 드릴까요?"라고 대화로 묻는다 (별도 팝업 없음).
- 맞히면 "그럼 이제 만들어 볼까요?" → **만드는 몽타주** → **게임 상자 뽑기처럼 상자 열기** → **완성품 등장** 순서로 보여준다 (2026-10-18, 상자 열기는 2026-10-19 사용자 요청으로 추가).
  - **만드는 몽타주 (2026-10-19 사용자 요청으로 바꿈, 토이 스토리 2의 우디 수리 장면 같은 클로즈업 컷 연출을 참고)**: 화면 위아래에 검은 띠가 생기고(영화 화면), 클로즈업 컷 6개가 번쩍 끊기며 이어진다. 위 띠에 "🪚 2/6 톱질" 같은 단계, 아래 띠에 루소 자막. 컷마다 배경을 다른 각도로 천천히 당겨 찍는다.

    2. 🪚 톱질: 작업대 위 나무토막에 루소 손이 톱질, 톱밥이 날리고 "쓱싹"
    3. 🔨 끌로 깎기: 끌을 대고 망치로 세 번 내려칠 때마다 나무 조각이 튀고 화면이 들썩, 토막 → 대충 깎은 모양 → 매끈한 인형으로 바뀜 ("뚝! 딱! 뚝딱!")

## 8. 화면 구성

**루소의 작업실 장면 하나**에서 모든 단계를 진행한다. 목공소 배경 그림, 루소(허리 위), 말풍선, 앞쪽 테이블로 이루어지고, 단계마다 말풍선과 테이블 위 물건만 바뀐다.

```
│        (루소, 크게)      💬 가만있자~             │
│                            날 수 있나요?        │
│ ━━━━━━━━━━━━━━━━ 테이블 ━━━━━━━━━━━━━━━━━━━━━ │
│   [예] [아마도요] [모르겠어요] [아마 아닐걸요] [아니요] │
└──────────────────────────────────────────────┘
  ↩ 이전으로                                처음으로
```

| 단계 | 말풍선 | 테이블 위 |
|---|---|---|
| 시작 | 오늘은 뭘 만들어 드릴까요? | [시작하기], 방법 안내 한 줄. 왼쪽 벽에 "많이 만든 작품 TOP 5" 메모, 장면 아래에 "목각인형 그림: 켜짐 (오늘 N/50장)" |
| 주제 선택 | 어떤 걸 만들어 드릴까요? | 나무 상자 3개 (동물 / 음식 / 인물·캐릭터) |
| 질문 | 질문 | 답 버튼 5개 (키보드 1~5) |
| 추측 | 혹시… ○○ 만들어 드릴까요? | [맞아요!] [아니에요] |
| 만드는 중 | 그럼 이제 만들어 볼까요? → 장면 전체가 몽타주로 바뀌고 대사는 아래 자막으로 | (몽타주가 테이블까지 덮음, 7절) |
| 상자 열기 | 완성품을 상자에 담았어요~ → 액션별 대사 (말풍선은 위로) | 테이블 위로 떨어지는 나무 상자 (7절) |
| 완성 | 짜잔! ○○ 완성이에요 | 왼쪽에 목각인형 그림과 나무 명패, 명패 아래 [📤 공유하기] (누르면 그 자리에 "링크를 공유해주세요"와 공유 링크), 오른쪽에 "N번 만에 맞혔어요", 흉내 낸 배우, [하나 더 만들기] [다른 주제] |
| 못 맞힘 | 뭘 만들어 드리면 될까요? | 입력창 → "다음엔 꼭 만들어 드릴게요" → [다시 하기] |

- **많이 만든 작품 TOP 5**: 루소가 맞혀서 만든 횟수("맞아요"를 누른 횟수)가 많은 정답 5개를 이름, 주제, 횟수로 글씨만 보여준다. 2026-10-17부터 세기 시작했다 (그전 기록 없음). 저장은 로컬 `.data/wins.json`, 배포 KV `stats:wins`.
- **작품 공유** (2026-10-17 추가)
  - [📤 공유하기]: 누르면 버튼 자리에 "링크를 공유해주세요" 문구와 공유 링크 칸이 나온다. 링크 칸을 누르면 전체 선택돼서 바로 복사할 수 있다. (처음엔 기기 공유 창·그림 저장 버튼도 있었는데 사용자 요청으로 링크 표시만 남김)
  - 공유되는 링크는 결과 페이지 `/share/<주제>/<후보>?q=<맞힌 질문 수>` (`lib/share.mjs`). 열면 목각인형 그림, 명패, 흉내 낸 배우, [나도 해보기]가 나온다. og 태그가 있어서 카카오톡·슬랙에 붙이면 그림이 미리보기로 뜬다.
  - 새 키나 비용 없음.
- 질문 번호는 "질문 N"으로만 표시한다.
- 모바일은 말풍선 → 루소 → 테이블 순서로 세로로 쌓는다.

## 9. 기술 구성

배포 주소: https://russo-workshop.dokh.workers.dev (Cloudflare 무료 요금제, 개인 계정, 2026-10-17 첫 배포)

| 역할 | 로컬 개발 (`npm run dev`) | 배포 (`npm run deploy`) |
|---|---|---|
| 화면, 루소·배우 그림 | Node 서버가 `public/`, `assets/` 를 보냄 | Workers 정적 자산 (`scripts/build-assets.mjs` 가 `dist/` 로 모음) |
| 서버 (그림·Jev 호출, 키 숨김) | `server.mjs` | Cloudflare Workers (`worker/index.mjs`) |
| `/api` 처리 | 둘이 같은 코드 `lib/api.mjs` | ← |
| 저장 (목각인형 그림, 배우 배정, 하루 생성 수, 맞힌 횟수, 못 맞힌 기록) | `.data/` 폴더 (`node/store-fs.mjs`) | **Workers KV 하나** (`worker/store-kv.mjs`). 과제용이라 카드 등록이 필요 없는 KV만 쓰고 D1·R2는 쓰지 않음 |
| 판단 표 | `data/tables/*.json` 을 매번 읽음 | 같은 파일을 배포할 때 묶어서 올림 (판단 표를 바꾸면 다시 배포) |
| 설정·키 | `.env` | `wrangler.jsonc` 의 vars + Workers Secrets |

- **필요한 키**: Jev(TypeSafe), OpenAI API(이미지). 배포에는 `npx wrangler secret put OPENAI_API_KEY`, `npx wrangler secret put TYPESAFE_API_KEY` 로 넣는다.
- **API 키는 코드나 저장소에 넣지 않는다.**
- **이미지 생성은 갈아 끼울 수 있는 부품(어댑터)으로 분리한다** (`lib/image.mjs` 의 PROVIDERS).
- **정답 그림은 압축한 JPG(약 100KB)로 받는다.** 무료 Workers의 요청당 CPU 10ms 제한 안에서 처리하고 화면도 빨리 뜨게 하려고. 처음엔 webp였는데, 공유 링크 미리보기(카카오톡 등)가 webp를 못 보여줄 수 있어서 JPG로 바꿨다. 예전에 저장된 png·webp 그림은 그대로 쓴다.
- **같은 정답을 두 번 그리지 않는다.** 처음 공개될 때 한 번 그려 저장하고 다음부터 꺼내 쓴다. 여러 서버가 동시에 그리지 않도록 KV에 "그리는 중" 표시(3분 뒤 자동 삭제)를 둔다.
- 로컬에서 그린 그림은 `node scripts/seed-kv.mjs` 로 배포 KV에 옮길 수 있다 (첫 배포 때 11장 옮김).
- KV 무료 한도: 쓰기 하루 1,000번. 새 그림 1장에 쓰기 약 6번이라 하루 상한 50장이면 충분하다.
- OpenAI 구독과 API 결제는 별개다.

## 9-1. 관리 페이지 (2026-10-18 사용자 요청으로 추가)

주소 `/admin`. 비밀번호(`ADMIN_PASSWORD`, Workers Secrets에 사용자가 직접 넣음)로 잠그고, 로그인하면 12시간 유지한다 (서명한 쿠키).

| 묶음 | 기능 |
|---|---|
| 현황 | 오늘 그림 생성 수 / 상한, 오늘 창고 뒤지기 수 / 상한, 맞힌 횟수 합계, 못 맞힌 기록 수, 창고에서 찾아 맞힌 정답 수 |
| 스위치 | TOP 5 표시, 주제별 열기·닫기, 창고 뒤지기 켜기·끄기 (끄면 판단 표로만 진행), 그림 생성 켜기·끄기 (끄면 새 그림을 그리지 않음. 이미 그린 그림은 계속 나옴) |
| 상한 | 하루 그림 생성 상한, 하루 창고 뒤지기 상한 (비우면 배포 설정값) |
| 초기화 | TOP 5(맞힌 횟수), 못 맞힌 기록, 오늘 사용량(그림·창고 뒤지기). 누를 때 한 번 더 확인 |

- 설정은 저장소에 키 하나로 둔다 (로컬 `.data/settings.json`, 배포 KV `settings`). 다시 배포하지 않고 바로 반영된다.
- 넣지 않은 것: 작품 갤러리·그림 삭제, 기록 목록 보기, 관리 페이지에서 후보 추가, 난이도 조절.

## 12. 개발 순서

1. 동물 주제 하나로 후보 50개, 질문 50개, Jev 판단 표 만들기 → 게임 로직 (확률 갱신, 질문 선택, 추측, 재추측)
2. 화면: 시작 → 주제 선택 → 질문 → 추측 → 정답 공개(글씨만) / 졌어요, 이전으로
3. Cloudflare 배포 (Workers + KV) ← **여기까지가 최소 제출선** (2026-10-17 배포)
4. 정답 이미지: Jev 캐릭터 고르기 → OpenAI 이미지 생성 → 저장(배포는 KV), 하루 상한
5. 루소 포즈 5장과 대사
6. 음식, 인물·캐릭터 주제 데이터 추가 (2026-10-17 둘 다 완료, 주제마다 Jev 판단 표 3초·$0.01)

각 단계가 끝나면 실제로 플레이해 보고 다음 단계로 넘어간다.
