## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 이름 | **루소 목공소** (처음 이름 "뚝딱 루소"에서 변경) |
| 한 줄 소개 | 사용자가 마음속으로 정답을 떠올리면, 목수 루소가 질문으로 좁혀가며 맞히는 스무고개 웹 게임 (아키네이터 방식) |
| 목적 | 사내 AI 에이전트 강의 과제. 조건: 흥미 위주 마이크로 서비스, OpenAI가 아니어도 됨, **Jev를 포함한 여러 API 활용**, **배포까지**, 고도화는 불필요 |
| 대상 | 사내 동료 |
| 환경 | **PC 웹사이트**. 모바일은 화면이 깨지지 않는 정도만 대응 |
| 진행자 | 키글(KIGLE) 캐릭터 **루소** (안킬로사우루스, 목수) |
| 배포 | Cloudflare |

**콘셉트**: 목수 루소가 "오늘은 뭘 만들어 드릴까요? 아저씨가 맞혀볼게요!" 하고 스무고개로 사용자가 원하는 것을 맞힌다. 맞히면 "그럼 이제 만들어 볼까요?" 하고 뚝딱뚝딱 깎아서, 키글 캐릭터가 정답을 흉내 낸 **목각인형**을 만들어 준다. (2026-10-17 사용자 요청으로 변경)

**핵심 목표 (이것만 만든다)**
1. 루소가 테이블 건너편에서 질문하고, 사용자는 버튼으로 답한다.
2. 답변을 보고 정답을 좁혀가는 판단은 **Jev**에게 맡긴다.
3. 맞히면 루소가 만드는 연출 뒤에 **키글 캐릭터가 정답을 흉내 낸 목각인형 그림**을 보여준다.

**하지 않을 것**
- 아키네이터의 지니 그림, 로고, 이름을 따라 쓰지 않는다. 진행 방식만 참고한다.
- 사용자가 맞히는 모드는 만들지 않는다. 루소가 맞히는 모드만 만든다.
- 뽀로로 등 외부 라이선스 캐릭터는 흉내 배우로 쓰지 않는다. 코코비 세계관 캐릭터만 쓴다.
- 13절 "만들지 않는 것"에 적힌 기능은 과제 범위 밖이므로 추가하지 않는다.

## 2. 주제와 데이터

- **주제 3개**: 동물 / 음식 / 인물·캐릭터
- **후보**: 주제당 50개, 총 150개. 목록 밖 정답은 맞히지 못한다 (정상 동작으로 본다).
- **질문 목록**: 주제당 약 50개. 개발할 때 Claude Code로 작성한다.
- **Jev 판단 표**: 후보 × 질문마다 "이 후보는 이 질문에 '예'일 확률" (0~1). 50 × 50 × 3 = **약 7,500칸**. 개발할 때 Jev로 미리 채운다.
- **흉내 묘사 문장**: 후보 150개마다 "키글 캐릭터가 이 정답을 어떻게 흉내 내는지" 한두 문장. 개발할 때 Claude Code로 작성한다.

판단 표 예시 (값은 설명용):

| 후보 | 날 수 있나요? | 다리가 4개? | 물에서 살아요? |
|---|---:|---:|---:|
| 펭귄 | 0.05 | 0.02 | 0.80 |
| 고양이 | 0.01 | 0.97 | 0.05 |
| 독수리 | 0.97 | 0.02 | 0.03 |

**인물·캐릭터 후보 기준** (2026-10-17 사용자 결정)
- **외부 캐릭터(피카츄, 뽀로로, 엘사 등)도 후보에 넣고, 맞히면 목각인형도 만든다.** 비상업 사내 과제라는 이유로 사용자가 선택했다. 흉내 배우는 여전히 키글 캐릭터만 쓴다.
- 프롬프트에는 캐릭터 이름을 넣지 않고 특징(색, 의상, 소품)만 쓴다. 이미지 모델이 거부하면 나무 명패만 보여준다.
- **정치인**: 현역·최근 정치인은 넣지 않는다. 세종대왕, 이순신, 링컨처럼 오래전 역사 인물만 넣고, 논란이 큰 인물(독재자 등)은 제외한다.
- **현역 유명인**: 논란 없는 운동선수·연예인 위주로 10명 정도 넣는다. 그림에는 이름 없이 의상·소품만 쓴다.
- **구성 (50명, 대략)**: 역사 인물 12 + 동화·전래·고전 인물 12 + 외부 캐릭터 12 + 현역 유명인 10 + 직업 인물 4
- 인물은 성별을 적어 두고(6절 배우 고르기 규칙), 캐릭터처럼 성별이 애매하면 비워 둔다.

**개발 순서상 주의**: 판단 표 전체를 만들기 전에 **동물 주제 하나(2,500칸)로 먼저 시험**해서 Jev 비용, 속도, 판단 품질을 확인한다.

## 3. AI 역할 분담

핵심 원칙: **판단은 Jev, 계산은 코드, 그림은 이미지 API.** Jev는 문장을 생성하지 않고, 주어진 보기 중 선택하거나 확률을 판단만 한다.

| 작업 | 담당 | 시점 |
|---|---|---|
| 질문 목록, 흉내 묘사 문장 작성 | Claude Code (팀 플랜 구독, API 불필요) | 개발할 때 |
| 후보 × 질문 판단 표 채우기 | **Jev** (Noul) | 개발할 때 |
| 다음 질문 고르기, 확률 갱신, 추측 시점 판단 | 코드 (판단 표 사용) | 게임 중 |
| 정답을 흉내 낼 캐릭터 고르기 | **Jev** (Choice) | 게임 중, 정답이 처음 공개될 때 |
| 정답 이미지 생성 | OpenAI 이미지 API (저품질) | 게임 중, 정답이 처음 공개될 때 |
| 루소 포즈, 그림체 프롬프트 시험 | imagegen 스킬 | 개발할 때 |

**사용할 모델과 서비스**
- Jev: TypeSafe의 System One 모델 (예: `jev-1.14.0`). 문서: https://docs.typesafe.ai/llms.txt
  - 기본 도구: Noul(예/아니오 확률), Choice(보기 중 선택), Score(정도)
  - 한 요청에 질문 여러 개를 함께 보낼 수 있다. 요청당 컨텍스트 64k 토큰, 질문당 32k 토큰
- 이미지: OpenAI gpt-image 계열, **저품질(low)**. imagegen 스킬과 같은 계열이라 개발 때 맞춘 프롬프트를 그대로 쓸 수 있다. 참고 이미지 입력 지원 여부와 정확한 가격은 공식 문서로 확인한다.
- **imagegen 스킬은 개발할 때만 쓰는 도구다.** 배포된 사이트는 게임 중에 이 스킬을 부를 수 없다. 게임 중 이미지는 서버가 OpenAI 이미지 API를 직접 호출한다.
- 게임 중에 쓰는 외부 API는 **Jev와 OpenAI 이미지 API 두 개**다. LLM(Claude API)은 쓰지 않는다.

## 4. 게임 진행

### 답변 방식
- 버튼 5개: **예 / 아마도요 / 모르겠어요 / 아마 아닐걸요 / 아니요**
- 키보드 단축키 1~5
- 자유 입력(타이핑)은 없다.

| 버튼 | 확률 계산 반영 |
|---|---|
| 예 | 강하게 반영 |
| 아마도요 | 약하게 반영 |
| 모르겠어요 | 반영하지 않음 |
| 아마 아닐걸요 | 반대로 약하게 반영 |
| 아니요 | 반대로 강하게 반영 |

- **후보는 답변 하나로 지우지 않는다.** 확률만 조정해서 사용자의 실수나 판단 기준 차이(예: "토마토는 과일인가요?")를 회복할 수 있게 한다. 판단 표 값이 0이나 1이어도 계산할 때는 작은 여유를 둬서 확률이 0이 되지 않게 한다.
- **이전으로**: 바로 앞 답변을 취소하고 그 질문으로 돌아간다. 확률은 남은 답변으로 다시 계산한다.

### 진행 순서 (수치는 코드 상수로 둔다)
1. **질문**: 판단 표를 보고 남은 후보를 가장 잘 갈라주는 질문을 고른다. 답변마다 확률을 갱신한다.
2. **추측**: 1위 후보 확신도가 기준을 넘거나 질문 **20개**에 도달하면 추측한다.
3. **재추측**: 틀리면 그 후보만 확실히 제외하고 질문을 2~3개 더 한 뒤 다시 추측한다. 재추측은 **최대 3회**.
4. **끝**
   - 맞히면 → 정답 공개 (5절)
   - 재추측까지 다 틀리면 → "졌어요" 화면. 정답을 입력받아 **기록만** 남긴다 (자동 반영, 검사, 승인 없음). 나중에 후보를 보강할 때 참고한다.

### 못 맞힌 정답 반영 (A 방식: 개발자가 직접 추가, 2026-10-17 결정)
- 게임이 스스로 배우지는 않는다. 못 맞힌 정답은 기록만 쌓이고, 개발자가 모아서 후보에 추가한다.
- 순서: `npm run losses` 로 자주 나온 정답 확인 → `data/topics/<주제>.mjs` 에 후보 추가 (이름, 영어 이름, 성별, 그림용 설명 as, 흉내 묘사 mimic) → `node scripts/build-table.mjs <주제>` 로 **새 후보 줄만** Jev가 채움 (1명당 약 1초, $0.0002) → 서버 다시 켜기
- 질문 문구를 고쳤을 때는 `--all` 로 그 주제 전체를 다시 채운다 (약 3초, $0.01).
- 첫 반영: 인물·캐릭터에 카리나 추가.

## 5. 정답 이미지 (루소가 만든 목각인형)

- **배우 캐릭터가 정답을 흉내 낸 모습을 깎은 목각인형**이다. 의상, 포즈, 소품까지 나무로 깎은 것처럼 그린다.
  - 동물: 펭귄 → 펭귄 옷을 입고 뒤뚱거리는 코코 목각인형
  - 음식: 사과 → 커다란 사과를 든 러비 목각인형
  - 인물: 손흥민 → 흰색 축구 유니폼 7번에 카메라 세리머니를 하는 잭잭 목각인형
- 프롬프트에는 **실제 이름을 넣지 않고** 2절의 흉내 묘사 문장(특징)만 넣는다.
- **화풍**: 밝은 원목, 나뭇결과 끌 자국이 보이고 무광 물감을 얇게 칠한 수제 나무 장난감. 작업대 위에 서 있고, 뒤는 흐릿한 목공 작업실. 배우의 원본 이미지(`assets/characters/`)를 참고로 함께 넣어 생김새를 맞춘다.
- **글씨는 이미지 안에 넣지 않는다.** 정답 이름은 웹 화면의 나무 명패에 쓴다.
- **생성 시점**: 미리 만들지 않는다. **정답이 처음 공개될 때** 캐릭터 고르기(Jev) → 이미지 생성(OpenAI) → 저장(배포는 Workers KV)한다. 다음부터는 저장된 이미지와 캐릭터를 쓴다.
- **품질**: 저품질(low). 실측 장당 약 15~18초.
- **하루 생성 상한**: 예: 하루 50장. 상한은 설정값(환경 변수)으로 두고, 오늘 생성 수는 저장소에 센다.
- **생성 실패나 상한 초과 시**: 나무토막 그림과 정답 명패만 보여준다.
- 인터넷 이미지는 쓰지 않는다 (저작권, 그림체 불일치).

## 6. 흉내 배우

### 배우 5명
루소는 진행자이므로 배우에서 제외한다.

| 캐릭터 | 영문 | 종 | 성별 | 특징 | 어울리는 유형 |
|---|---|---|---|---|---|
| 러비 | lobi | 공룡 (주인공 가족) | 남 | 주인공, 노란 몸, 빨간 지그재그 니트 | 슈퍼스타, 주인공감 |
| 코코 | coco | 공룡 (주인공 가족) | 여 | 주인공, 분홍 몸, 분홍 머리 경단, 보라 원피스, 흰 깃 | 슈퍼스타, 주인공감 |
| 벨 | bell | 렙터 | 여 | 파란 몸, 빨간 모자, 활발함 | 운동선수, 활동적 |
| 잭잭 | jack jack | 티라노 | 남 | 빨간 몸, 초록·노랑·갈색 줄무늬 티셔츠, 개구쟁이 | 운동선수, 장난기 |
| 엘론 | elon | 스테고 | 남 | 주황 몸, 큰 안경, 보라 옷, 똑똑함, 부잣집 | 과학자, 사업가, 똑똑한 인물 |

다섯 명 모두 아이 캐릭터라서, 어른 인물도 **아이가 코스프레하는 귀여운 느낌**으로 통일된다.

### 고르는 방법
- Jev Choice에 배우 5명의 프로필과 정답의 흉내 묘사 문장을 주고 "흉내 내기 가장 어울리는 캐릭터"를 고르게 한다.
- **인물은 성별을 맞춘다.** 여성 인물은 코코, 벨 / 남성 인물은 러비, 잭잭, 엘론 중에서만 고른다. 동물, 음식, 성별이 없거나 애매한 대상은 다섯 명 모두 후보.
- 한 번 정해지면 이미지와 함께 고정된다.

## 7. 진행자 루소 연출

### 루소 설정
- 키글 캐릭터, 안킬로사우루스, 직업은 소방관·목수. **이 게임에서는 목수로만 연출한다.**
- 생김새: 베이지·회색 몸, 파란 모자, 흰 셔츠, 파란 멜빵바지, 땀방울

### 콘셉트
- 사용자는 루소의 작업실에서 **테이블을 사이에 두고 루소와 마주 앉아** 대화한다. 루소는 허리 위로 크게 보이고, 답 버튼은 테이블 위에 놓인다.
- 루소가 사용자가 만들고 싶은 것을 스무고개로 맞힌다. 추측도 "혹시… ○○ 만들어 드릴까요?"라고 대화로 묻는다 (별도 팝업 없음).
- 맞히면 "그럼 이제 만들어 볼까요?" → 망치와 끌로 뚝딱뚝딱 깎는 연출(최소 약 3초, 그림이 늦으면 그동안 계속) → 완성된 목각인형을 테이블 위에 올려 보여준다.
- **흉내는 배우 캐릭터만 한다.** 루소는 진행자이자 만드는 사람이다.

### 말투
- **존댓말을 쓰는 친근한 옆집 아저씨**
- 감탄사: "허허", "어이쿠", "옳지!", "가만있자~"
- 말버릇: **"뚝딱!"**
- 사투리는 쓰지 않는다.

### 포즈 5장 (테이블 건너편 클로즈업, 배경 투명)
`node scripts/make-russo.mjs` 로 루소 원본(`assets/characters/russo.png`)을 참고해 생성한다. 허리 아래는 화면의 테이블이 가린다.

1. 기본 (손짓하며 말하기): 시작, 주제 선택, 추측
2. 고민 (턱 괴기): 질문
3. 기쁨 (엄지 척): 맞힘, 완성
4. 땀방울: 오답, 못 맞힘
5. 만들기 (망치와 끌로 나무 깎기): 만드는 중

움직임은 프레임 애니메이션 대신 통통 튀기, 흔들기, 망치질 들썩임과 "뚝딱!" 글자 효과로 처리한다.

## 8. 화면 구성

**루소의 작업실 장면 하나**에서 모든 단계를 진행한다. 벽(선반과 공구), 루소(허리 위), 말풍선, 앞쪽 테이블로 이루어지고, 단계마다 말풍선과 테이블 위 물건만 바뀐다.

```
┌──────────────────────────────────────────────┐
│ 루소 목공소                       동물 · 질문 7 │
├──────────────────────────────────────────────┤
│  🪚 🔨 🪵 (선반)                                │
│        (루소, 크게)      💬 가만있자~             │
│                            날 수 있나요?        │
│ ━━━━━━━━━━━━━━━━ 테이블 ━━━━━━━━━━━━━━━━━━━━━ │
│   [예] [아마도요] [모르겠어요] [아마 아닐걸요] [아니요] │
└──────────────────────────────────────────────┘
  ↩ 이전으로                                처음으로
```

| 단계 | 말풍선 | 테이블 위 |
|---|---|---|
| 시작 | 오늘은 뭘 만들어 드릴까요? | [시작하기], 방법 안내 한 줄 |
| 주제 선택 | 어떤 걸 만들어 드릴까요? | 나무 상자 3개 (동물 / 음식 / 인물·캐릭터) |
| 질문 | 질문 | 답 버튼 5개 (키보드 1~5) |
| 추측 | 혹시… ○○ 만들어 드릴까요? | [맞아요!] [아니에요] |
| 만드는 중 | 그럼 이제 만들어 볼까요? → 뚝딱뚝딱… | 나무토막 |
| 완성 | 짜잔! ○○ 완성이에요 | 왼쪽에 목각인형 그림과 나무 명패, 오른쪽에 "N번 만에 맞혔어요", 흉내 낸 배우, [하나 더 만들기] [다른 주제] |
| 못 맞힘 | 뭘 만들어 드리면 될까요? | 입력창 → "다음엔 꼭 만들어 드릴게요" → [다시 하기] |

- 질문 번호는 "질문 N"으로만 표시한다.
- 모바일은 말풍선 → 루소 → 테이블 순서로 세로로 쌓는다.

## 9. 기술 구성

배포 주소: https://russo-workshop.kimdohan2.workers.dev (Cloudflare 무료 요금제, 개인 계정, 2026-10-17 첫 배포)

| 역할 | 로컬 개발 (`npm run dev`) | 배포 (`npm run deploy`) |
|---|---|---|
| 화면, 루소·배우 그림 | Node 서버가 `public/`, `assets/` 를 보냄 | Workers 정적 자산 (`scripts/build-assets.mjs` 가 `dist/` 로 모음) |
| 서버 (그림·Jev 호출, 키 숨김) | `server.mjs` | Cloudflare Workers (`worker/index.mjs`) |
| `/api` 처리 | 둘이 같은 코드 `lib/api.mjs` | ← |
| 저장 (목각인형 그림, 배우 배정, 하루 생성 수, 못 맞힌 기록) | `.data/` 폴더 (`node/store-fs.mjs`) | **Workers KV 하나** (`worker/store-kv.mjs`). 과제용이라 카드 등록이 필요 없는 KV만 쓰고 D1·R2는 쓰지 않음 |
| 판단 표 | `data/tables/*.json` 을 매번 읽음 | 같은 파일을 배포할 때 묶어서 올림 (판단 표를 바꾸면 다시 배포) |
| 설정·키 | `.env` | `wrangler.jsonc` 의 vars + Workers Secrets |

- **필요한 키**: Jev(TypeSafe), OpenAI API(이미지). 배포에는 `npx wrangler secret put OPENAI_API_KEY`, `npx wrangler secret put TYPESAFE_API_KEY` 로 넣는다.
- **API 키는 코드나 저장소에 넣지 않는다.**
- **이미지 생성은 갈아 끼울 수 있는 부품(어댑터)으로 분리한다** (`lib/image.mjs` 의 PROVIDERS).
- **정답 그림은 webp(약 150KB)로 받는다.** 무료 Workers의 요청당 CPU 10ms 제한 안에서 처리하고 화면도 빨리 뜨게 하려고.
- **같은 정답을 두 번 그리지 않는다.** 처음 공개될 때 한 번 그려 저장하고 다음부터 꺼내 쓴다. 여러 서버가 동시에 그리지 않도록 KV에 "그리는 중" 표시(3분 뒤 자동 삭제)를 둔다.
- 로컬에서 그린 그림은 `node scripts/seed-kv.mjs` 로 배포 KV에 옮길 수 있다 (첫 배포 때 11장 옮김).
- KV 무료 한도: 쓰기 하루 1,000번. 새 그림 1장에 쓰기 약 6번이라 하루 상한 50장이면 충분하다.
- OpenAI 구독과 API 결제는 별개다.

## 12. 개발 순서

1. 동물 주제 하나로 후보 50개, 질문 50개, Jev 판단 표 만들기 → 게임 로직 (확률 갱신, 질문 선택, 추측, 재추측)
2. 화면: 시작 → 주제 선택 → 질문 → 추측 → 정답 공개(글씨만) / 졌어요, 이전으로
3. Cloudflare 배포 (Workers + KV) ← **여기까지가 최소 제출선** (2026-10-17 배포)
4. 정답 이미지: Jev 캐릭터 고르기 → OpenAI 이미지 생성 → 저장(배포는 KV), 하루 상한
5. 루소 포즈 5장과 대사
6. 음식, 인물·캐릭터 주제 데이터 추가 (2026-10-17 둘 다 완료, 주제마다 Jev 판단 표 3초·$0.01)

각 단계가 끝나면 실제로 플레이해 보고 다음 단계로 넘어간다.

## 13. 만들지 않는 것 (범위를 줄이면서 뺀 기능)

처음 기획에는 있었지만 과제 목표(질문 → Jev 판단 → 키글 캐릭터 이미지)에 필요 없어서 뺐다. 개발 중에 다시 넣지 않는다.

- 목록 밖 후보 찾기(LLM), 비슷한 후보를 가르는 즉석 질문, 모순 감지
- 학습 반영과 관리자 승인 대기 목록 (대신 4절 "못 맞힌 정답 반영"처럼 개발자가 직접 추가)
- 관리자 페이지 (난이도 설정, 비용 화면)
- 작업 일지 (결정적 질문, 남은 후보 수 변화)
- 진행 표시 (설계도 → 뼈대 → 거의 완성)
- 지난 답변 아무거나 고치기 (바로 앞 답변 취소만 남김)
- 루소 포즈 7장 (5장으로 줄임), 흉내 배우 쏠림 방지 상한
